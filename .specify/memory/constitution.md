# Стройова (Stroiova) Constitution

Мобільна idle-гра для iOS і Android: сатира на армійський документообіг. Соло-розробка, Expo (React Native) + TypeScript. Ця конституція — правила, які перевіряє кожна специфікація, план і задача (`/speckit-plan`, `/speckit-analyze`, `/speckit-implement`). Деталі — в `docs/`.

## Core Principles

### I. Специфікація — єдине джерело правди (NON-NEGOTIABLE)
Код пишемо лише за специфікацією в `specs/NNN-*/spec.md` і рішеннями в `docs/decisions.md`. Якщо код, макет і специфікація розходяться — спершу виправляємо специфікацію (або фіксуємо нове рішення), потім код. Нова механіка без рішення в `docs/decisions.md` не з'являється. Числа балансу живуть лише в `balance/` і контенті, ніколи не зашиваються в UI-код.

### II. Чиста економіка, спільна із симулятором
Економіка — чистий TypeScript-модуль без React, I/O і годинника (`packages/economy` або `src/economy`). Час, випадковість (seed) і конфіг передаються параметрами. Той самий модуль крутить і гру, і симулятор балансу; модель-еталон — `balance/sim.js` (v6). Будь-яка зміна формул супроводжується прогоном симулятора й оновленням `balance/preset-*.json`. Дохід рахується від різниці міток часу, а не від тіків; переведений назад годинник не дає доходу.

### III. Тести перед злиттям
Кожен критерій приймання (AC) специфікації має автоматичний тест або явно позначений ручний сценарій. Модуль економіки — юніт-тести з фіксованим seed і золотими значеннями з симулятора. UI-потоки — Maestro e2e для онбордингу, покупки, повернення офлайн. Міграції збережень — тест на кожну попередню версію схеми.

### IV. Червоні лінії змісту (NON-NEGOTIABLE)
Сміємося з паперу, не з людей. Ніколи: загиблі, поранені, полон, СЗЧ, ВЛК, виплати родинам і бойові виплати, ТЦК і мобілізація; реальні імена, номери частин, символіка ЗСУ й Міноборони; абревіатура «УПА» в назвах; мат; куріння; зброя як жарт; боєприпаси на дроні. Слова «станція» в грі немає («потоки» й «погодження»). «Погоджено» — лише штамп, не бренд. Тексти проходять правила `docs/anti-slop.md` і вичитку носіями. Генеративна графіка в релізі заборонена.

### V. Правила сторів і приватність
Реклама лише за винагороду (AdMob), без міжекранної. Без ATT; Google UMP лише в ЄЕЗ/UK/CH перед першим роликом. Аналітика анонімна (install_id, без IP), вимикач у налаштуваннях. Оцінка лише системним вікном. Про фонд пишемо лише в «Про гру» й описі стору, ніколи біля покупок (Apple 3.2.2). Жодна покупка не схожа на пожертву.

### VI. Дизайн-система й доступність
Інтерфейс збирається з токенів і компонентів `design/system/` (кольори, шрифти, штампи). Штамп — синьо-фіолетовий, червоний лише для тривог зі словом. Ціль дотику ≥ 44 px, контраст тексту ≥ 4,5:1, колір ніколи не єдиний носій стану, Reduce Motion підтримано, масштаб шрифту до 1,3×. Перевірка на iPhone SE (375×667).

### VII. Аналітика за планом
Події лише з `analytics/tracking-plan.yaml` (типізована обгортка `track()`, згенерована з YAML). Нова подія — спершу в план, потім у код. Тапи агрегуються, без події на кожен тап.

### VIII. Простота
Один застосунок, локальне збереження (zustand + MMKV), без власного бекенду, доки специфікація прямо його не вимагає. Контент (телеграми, журнали, тексти) — JSON, оновлюється через expo-updates. YAGNI: не будуємо систем під майбутні рівні наперед.

## Технічні обмеження

Expo SDK (актуальний стабільний), TypeScript strict, react-native-skia + reanimated для графіки й анімацій, expo-haptics, zustand + MMKV, break_infinity.js для великих чисел, react-native-google-mobile-ads, RevenueCat, PostHog (EU), Sentry, expo-notifications (лише локальні), expo-updates. iOS: збірка Xcode 26 / SDK iOS 26; Android: target API 36. Мова — українська (рядки винесені, готові до локалізації).

## Робочий процес

1. Нова фіча: `/speckit-specify` → `/speckit-clarify` → `/speckit-plan` → `/speckit-tasks` → `/speckit-analyze` → `/speckit-implement`.
2. Наявні специфікації 001–010 уже написані: для них починаємо з `/speckit-plan`.
3. Рішення змінюється — новий рядок у `docs/decisions.md` з датою, потім правка специфікацій.
4. Коміти малі, гілка на фічу (`NNN-slug`), PR із посиланням на специфікацію й AC.

## Governance

Конституція важить більше за будь-яку специфікацію чи план. Зміни — лише через правку цього файлу з новою версією й датою та записом у `docs/decisions.md`. `/speckit-analyze` перед кожною реалізацією перевіряє відповідність принципам I–VIII.
