# Стратегія реалізації

9.10.2026. Як переходимо від специфікацій до коду. Порядок фіч — `docs/roadmap.md`, правила — конституція.

## Принципи

1. **Спершу ядро, потім ширина.** Повна гра на рівнях 1–2 з усіма системами (події, музей, монетизація) і закритий тест — до того, як писати рівні 3–5. Рівні 3–5 — це нові дані й 2–3 механіки на вже готовому рушії.
2. **Економіка — чистий модуль, перевірений симулятором.** `src/economy` — порт `balance/sim.js` на TypeScript. Тести порівнюють модуль із `sim.js` на тих самих seed (золоті значення). Розходження = баг.
3. **Контент — дані, рушій — код.** Телеграми, репліки, сюжет, музей, грамоти — JSON зі схемами Zod. Кожен PR проходить `tools/check_content.py` (і пізніше Zod-валідацію в CI). Вибір із пулів — «мішком» (рішення 41).
4. **Вертикальні зрізи.** Кожна фіча доходить до екрана, на якому її можна пограти, з тимчасовою графікою з дизайн-системи. Ілюстрації підміняються пізніше без зміни коду.
5. **Одна фіча — одна гілка — один PR.** `/speckit-plan` → `/speckit-tasks` → `/speckit-analyze` → `/speckit-implement`. Таски дрібні (≤ 1–2 год), кожен AC — тест або ручний сценарій.

## Як працювати з Claude Code

- Одна сесія — одна фіча. Перше повідомлення: «Працюємо над `specs/NNN-*`, починай з `/speckit-plan`».
- Після `/speckit-tasks` — `/speckit-analyze`, і лише тоді `/speckit-implement` по одній фазі задач.
- Зміна механіки чи числа під час коду: спершу рішення в `docs/decisions.md` і правка специфікації, потім код (принцип I).
- Будь-яка зміна формул: прогін `balance/sim.js`, оновлення пресета й золотих значень.
