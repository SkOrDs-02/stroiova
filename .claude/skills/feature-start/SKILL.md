# Старт фічі

Одна сесія — одна фіча — одна гілка — один PR (`docs/implementation-strategy.md`).

## Кроки

1. **Контекст.** Прочитай `.specify/memory/constitution.md`, `specs/NNN-*/spec.md`, рядок фічі в `docs/roadmap.md` і етап у `docs/implementation-strategy.md`. Знайди рішення, на які посилається специфікація (`grep -n "рішення" specs/NNN-*/spec.md`), і прочитай їх у `docs/decisions.md`.
2. **Залежності.** Перевір, що фічі з колонки «Залежить від» уже змерджені в main (є код і закриті задачі). Якщо ні — скажи Дмитру й запропонуй порядок.
3. **Гілка.** `NNN-slug` від свіжого `main` (як у `specs/`), якщо сесія не задала іншу.
4. **Стан артефактів.** Немає `plan.md` → `/speckit-plan`. Є план, немає `tasks.md` → `/speckit-tasks`. Є задачі → `/speckit-analyze`, і лише після чистого аналізу `/speckit-implement` по одній фазі. Є код і задачі розійшлися → `/speckit-converge`.
5. **Відкриті питання.** Усе, чого немає в специфікації чи рішеннях, збери списком і спитай одним повідомленням. Не вигадуй механік і чисел.
6. Коротко доповідай: що вже є, що робимо в цій сесії, що потрібно від Дмитра.

Під час реалізації: зміна механіки чи числа → скіл `decision`, зміна формули → `balance-change`, новий текст → `text-review`. Перед PR — агент `spec-guardian` по диффу.
