# Вичитка текстів

Правила: `.specify/memory/constitution.md` (принцип IV) і `docs/anti-slop.md`. Автоматика ловить лише слова, тон і передбачуваність ловить читання.

## Кроки

1. **Обсяг.** Без аргументу — змінені рядки: `git diff --unified=0 -- content docs/texts.md` (плюс рядки інтерфейсу в `src/`, якщо є).
2. **Автоматика.** `python3 tools/check_content.py`. Помилки червоних ліній виправляються завжди.
3. **Червоні лінії вручну** (regex не бачить сенсу): смерть, поранення, полон, СЗЧ, ВЛК, виплати, ТЦК і мобілізація, реальні частини, імена, символіка ЗСУ й Міноборони, «УПА», мат, куріння, зброя чи боєприпаси як жарт, слово «станція», «Погоджено» як бренд. Жарт б'є по паперу, не по людях.
4. **Анти-слоп** за таблицею `docs/anti-slop.md`: пишний зачин, слова-підпірки, кальки й русизми, «не просто X, а Y», трійки, драматичне тире, мораль у кінці, рівний ритм, вигадані цифри, залишки чат-бота й емодзі, пафос. У телеграмі має бути одна реальна деталь документообігу, жарт не пояснюємо.
5. **Форма.** Обидві статі протагоніста, де є звертання (рішення 19). Ліміти полів зі специфікацій: `note` ≤ 60, кнопка ≤ 22 знаки (03). Нового поля без схеми немає.
6. **Звіт.** Таблиця: `id | проблема | правило | пропозиція`. Панчлайни не переписуй сам: пропонуй варіант, рішення за Дмитром. Рядки, які треба звірити з живим стройовиком, познач окремо.

Великий обсяг (пул, рівень) віддай агенту `content-reviewer`: він працює лише на читання й повертає таблицю.
